# Ledger Guard

Ledger Guard - сервис для сверки событий финансовой операции, которые приходят из нескольких систем.

Идея проекта появилась из типичной проблемы распределённых систем: одна операция проходит через несколько сервисов, и каждый из них фиксирует только свой этап. Сам по себе факт получения события ещё не означает, что операция завершилась корректно. Часть событий может не прийти, данные могут различаться, а отдельные этапы могут оказаться записаны в неправильном порядке.

В проекте рассматривается сценарий пополнения инвестиционного счёта. Операция состоит из четырёх событий:

1. `DEPOSIT_CREATED` - создано пополнение
2. `MONEY_DEBITED` - деньги списаны со счёта клиента
3. `TRANSFER_COMPLETED` - перевод завершён
4. `FUNDS_CREDITED` - средства зачислены на инвестиционный счёт

Ledger Guard собирает события одной операции и проверяет:

- получены ли все обязательные этапы
- совпадают ли сумма, клиент и валюта
- пришли ли события от ожидаемых систем
- соблюдён ли порядок выполнения операции
- нет ли повторных или конфликтующих событий

По результатам сверки операция получает один из статусов:

- `PENDING` - часть событий ещё не получена
- `MATCHED` - операция прошла сверку
- `AMOUNT_MISMATCH` - суммы в событиях различаются
- `DATA_MISMATCH` - обнаружено другое расхождение в данных
- `INVALID_SEQUENCE` - нарушен порядок событий

## Текущее состояние

Сейчас реализовано локальное ядро сервиса. Оно читает события из JSON-файла, преобразует их в доменные объекты и выполняет сверку по заданным правилам.

На этом этапе я специально не подключал брокер сообщений и базу данных. Сначала мне было важно отдельно проверить предметную логику и зафиксировать её тестами. Следующий этап проекта - перейти от обработки одного файла к приёму потока событий через Apache Kafka и сохранению состояния операций в PostgreSQL.

## Пример события

```json
{
  "event_id": "event-1",
  "operation_id": "operation-1",
  "event_type": "DEPOSIT_CREATED",
  "source": "funding_service",
  "client_id": "client-1",
  "amount": "15000.00",
  "currency": "RUB",
  "occurred_at": "2026-07-24T12:00:00+00:00"
}
```

Входной файл должен содержать массив событий одной операции.

## Запуск

Проект использует Python 3.13.

```bash
python3.13 -m venv .ledgerguard
source .ledgerguard/bin/activate
pip install -e ".[dev]"
```

Запуск со стандартным примером:

```bash
python -m ledger_guard
```

Запуск со своим файлом:

```bash
python -m ledger_guard path/to/events.json
```

Тесты:

```bash
pytest
```

## Дальнейшее развитие

Дальше локальный движок будет встроен в событийную архитектуру:

```text
генератор событий
        ↓
небольшой HTTP-шлюз на Go
        ↓
Apache Kafka
        ↓
Python-обработчики
        ↓
PostgreSQL
        ↓
API для просмотра результатов сверки
```

Также планируется добавить параллельную обработку операций, повторные попытки для временных ошибок и отдельную очередь для событий, которые не удалось обработать.
